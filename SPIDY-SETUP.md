Run the portfolio locally with `node server.mjs` or `./start-preview.ps1`. Node.js 22+ is required; there are no packages to install. Open http://127.0.0.1:5173/?motion=full.

Web Swing works entirely in the browser. Ask Spidy works with saved public portfolio answers immediately. To enable live AI:

1. Copy `.env.example` to `.env` in this folder.
2. Set `GROQ_API_KEY` in `.env` to your Groq key. Keep it private; do not put it in frontend code or commit it.
3. Restart `node server.mjs`. Spidy will show “Groq AI configured”; a successful generated answer shows “Groq AI · live reply”.

The default model is `openai/gpt-oss-20b`, using Groq strict structured output. Free limits depend on your account and may change. Each request selects relevant resume/project facts (including the latest visitor topic for follow-ups), instead of sending the entire portfolio on every call. Authentication failures, exhausted quotas, timeouts and invalid output fall back to saved facts with an explanatory notice. A Groq 429 starts a provider cooldown honoring `Retry-After`, or 60 seconds when absent, to avoid repeated calls during the limit. Backend diagnostics log only a reason and HTTP status, never provider bodies, credentials or chat text. A configured key alone does not establish a working connection; check an actual generated reply. Greetings can return without citations, while factual questions still require known source IDs.

Edit approved facts, saved answers and link actions in `public-knowledge.mjs` when adding projects. It includes a curated transcription of the supplied resume: degree and CGPA through Semester VI, HSC results, coursework, project stacks/contributions, CSI activities, skills, and the document's certificate entries. Resume results are a document snapshot; certificate entries are not independently verified employment records. Phone/postal details and private planning notes are excluded from chat context. When the resume changes, update these facts and saved answers together, then restart/redeploy. `info.txt` remains private planning material and is never used as chat context or served by the Node server. Chat transcripts are only kept in page memory. Live chat sends the current question, up to six recent messages and the selected public facts to Groq. Game best scores are stored locally in the visitor's browser.

Backend protections: same-origin JSON requests, bounded body/message/history/output size, per-IP and global rate limits, bounded concurrency and daily calls, server-held credentials, strict response shape, approved link IDs, output checks, no execution tools, and a scoped system prompt. Prompt/grounding checks reduce mistakes; they cannot prove every generated statement correct. Rate limits are in process memory; a deployment with multiple instances needs a shared limiter. Behind a proxy, the socket-based visitor limit may be shared by visitors; forwarded IP headers are not trusted automatically. In production, the server reads `PORT` and the platform's `APP_URL`/`SITE_URL`, and listens on `0.0.0.0`. `ALLOWED_ORIGIN` overrides the public origin when needed. `/healthz` is a public, data-free container health probe. Static-only hosting cannot run `/api/chat`.

Checks: `node --test tests/portfolio.test.mjs` (local HTTP sockets needed). These use a stub Groq response and do not make paid API calls.
